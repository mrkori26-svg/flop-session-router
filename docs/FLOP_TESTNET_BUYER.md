# FLOP buyer preparation — 2026-10-09

This extends the existing `FlopRuntimeAdapter`, routing decisions and economic gate. It does not open a channel, sign, submit a transaction or certify settlement.

Source: [official public draft 0.5.0](https://github.com/flop-labs/yellowpaper/blob/3c97bbc8d6ba68cf2ea003ab88bc154aafdf105e/yellowpaper.md), sections 6.5, 12, Appendix F/G and E.55. G.1 publishes logical extrinsics, not runtime metadata or call indices. E.55 explicitly marks the signed comparable quote/discovery contract PLANNED. No public testnet endpoint is embedded in this implementation.

`flop-router testnet-readiness --config examples/flop-public-testnet.disabled.json` reports concrete local and upstream blockers. `prepare-inference --db <existing-db> --decision <id> --intent <file> --config <file>` binds an existing, intact, eligible routing decision to known `open_channel` scalar parameters. Its result is PREPARED_BLOCKED_UPSTREAM with settlement UNVERIFIED. SLA/precision/settlement-class runtime bindings and wire encoding remain blocked. `base-unit` is a local metadata unit tag; FLOP uses 18 decimal places. SHA256 preparation hashes are local audit digests, not channel ids.

Configuration environments: local, devnet, public-testnet. Preparation defaults off. Pin `genesisHash` and `agentAccount` as lowercase 0x-prefixed 32-byte hex; set positive u128 `maxEscrowBaseUnits` and `maxTransactionFeeBaseUnits`, then explicitly enable `prepareEnabled` for offline preparation. All amounts and the u64 channel nonce are canonical decimal strings. Configuration is strictly validated; `purchaseEnabled:true` always fails closed. The environment overrides are FLOP_TESTNET_ENVIRONMENT, FLOP_TESTNET_PREPARE_ENABLED, FLOP_TESTNET_PURCHASE_ENABLED, FLOP_TESTNET_GENESIS_HASH, FLOP_TESTNET_AGENT_ACCOUNT, FLOP_TESTNET_MAX_ESCROW_BASE_UNITS and FLOP_TESTNET_MAX_TRANSACTION_FEE_BASE_UNITS. Boolean overrides accept only true/false.

Intent fields: measuredRoot, decodePolicyHash, enclaveKey, agentKey (32-byte hex), escrowBaseUnits (u128 decimal), channelNonce (u64 decimal). Account transaction nonce is a separate u32 runtime concern. Existing opening offers must bind chain/miner/model/precision/enclave, expiry, escrow floor and signature metadata. Signature presence is NOT verification, and offered RA-TLS/registry measurements are NOT accepted as attested. Forward terms are rejected until their verifier exists.

Reuse the canonical Signer's DPAPI CurrentUser and authenticated AF_PIPE boundary. Its current restricted operations do not authorize FLOP transactions; do not use its Technocore signatures or the test-only ephemeral signer as substitutes. A deployment must add a narrowly authorized custody operation only after actual runtime metadata, genesis and account/receipt-key bindings are available. Enclave transcript signatures are sr25519; a Technocore ed25519 DID does not establish buyer eligibility.

Economic safety: once an authorized execution throws, or completion recording fails, retain the reservation and mark outcome_unknown; never automatically run another provider. Reconcile externally before release/retry. Explicit failed results still release normally. HTTP inference requires explicit stream completion; an interrupted submitted stream does not fail over. HTTP completion and local EvidenceBundle PASS do not establish FLOP settlement.

First external inference requires upstream access/eligibility, funded account and approved signer binding, an official signed quote and attested external provider, runtime metadata/SDK and fee estimation, then independent finalized-chain evidence verification. The draft uses BABE + AlephBFT finalized prefixes; cooperative escrow is the full reserved-capacity payment, not metered unused-capacity refunds. Integration must freeze economic decisions during finality stalls and preserve transcript/receipt/settlement evidence in the existing EvidenceBundle pipeline. Real purchases remain disabled in this change.
